# Vklass notes

Observed 2026-11-02. There is no public API.

## Why the integration uses the calendar feed

Until October 2026 the integration logged in to the guardian site like a browser
(`auth.vklass.se/credentials` -> `signin`, then scraped `custodian.vklass.se`). Vklass has
since put a bot-protection layer (server header `baffin-bay-inlet`, "Threat Protection")
in front of both hosts:

- A plain HTTP client (curl, aiohttp) gets **403** "Threat Protection - Request Blocked".
- With a browser User-Agent the login page is replaced by an interactive "Verifying..."
  checkbox challenge.
- A logged-in browser session still gets 200 and JSON from `custodian.vklass.se`, and the
  old HTML and JSON shapes were unchanged, so only the login is out of reach. We do not
  try to defeat the challenge.

The calendar subscription host is **not** challenged, so the integration uses that.

## Calendar feed ("Prenumerera på schema")

The schedule page's subscribe dialog lists one link per child:

`webcal://cal.vklass.se/<hiddenGuid>.ics?includeLectures=true`

The GUID is the child's `hiddenGuid` (also in the schedule page data) and is the only
credential. `https://` works as well as `webcal://`. A GUID Vklass does not know answers
**200 with an empty body**, not 404. `includeLectures=false` leaves out lessons and keeps
only tests and homework.

iCalendar generated by DDay.iCal. About a month ahead. Timestamps use
`TZID=W. Europe Standard Time` (a Windows zone name) with a `VTIMEZONE` block.

| Kind | Shape |
|---|---|
| Lesson | timed `VEVENT`. `SUMMARY` and `DESCRIPTION` are the same three lines, `Svenska (9A/SV)\nSV \nABC`: title with group, short code, teacher. `LOCATION` is the room. |
| Test / homework | all-day (`DTSTART;VALUE=DATE`), titles like `Prov Meteorologi`, `Läxa i engelska`. `URL` points at `www.vklass.se/ExamInfo.aspx?id=...`. `DESCRIPTION` is `Torsdag 5 november 2026 kl: 13:05. `, the only place the due time appears. |

Not in the feed: cancelled or substitute flags (no `STATUS`), lunch, news, school-wide
holidays seen so far. Event `UID`s are GUIDs and were unique in a sample of 131 events.

## Lunch

Skolmaten publishes a week-menu RSS per school:
`https://skolmaten.se/api/4/rss/week/<school>?locale=sv`. One `item` per weekday: the date
is `pubDate` (midnight GMT), the dishes are the CDATA `description`, separated by
`, <br/>`. Days without a menu have an empty description. The school's page
(`skolmaten.se/<school>`) is accepted in the setup form and converted to this link.

## Old guardian-site endpoints (not used any more)

Behind a browser session they still worked on 2026-11-02:

- `GET /Calendar/Schedule/` listed children in the server HTML
  (`<input name="SelectedStudentIds" value="<numeric id>">`; the live DOM is rewritten by
  the SPA, so read the raw response).
- `POST /Events/FullCalendar` with `students=<numeric id>`, `start`, `end` returned JSON
  events including `cancelled` and `isSubstitute`. A GUID in `students` gives 400.
- `GET /Home/Welcome` held the per-child lunch cards.

If the bot protection is ever relaxed, or a session-cookie mode is added, these give back
the cancelled-lesson flag.
